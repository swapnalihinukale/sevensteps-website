Seven Steps: content replacement experience for the first review version

Specification, 15 October 2026. Show missing content at its intended location in the first review version, with a note explaining what to add. Website coding remains outside current authorization. The team has not selected a CMS or upload system.

Apply the [stop-slop skill](/Users/admin/.codex/skills/stop-slop/SKILL.md) to owner instructions and public copy: name the action, cut filler and formulaic contrasts, and use no em dashes. Preserve factual qualifications, quotation meaning and attribution.

**Help the photographer complete the draft**

Give each missing item a visible note at its intended location. Tell the photographer what belongs there and what to supply. Record the same item in the [content slot inventory](CONTENT-SLOT-INVENTORY.md), the shared completion list.

Use cleared material where available. Fill gaps with labelled placeholders that demonstrate composition and reading order. Do not present invented stories, borrowed reviews, stock photographs, prices or simulated films as the photographer's work or offers.

Add a persistent notice: **“Website draft. Add the missing photos and details using the content checklist.”** Keep local notes visible without hover or a hidden edit mode. Place them beside or below the relevant area, without covering the photograph's subject. Check mobile reading, keyboard access and screen-reader output.

**A content slot has one stable identity**

Assign each item a stable ID such as `HOME-HERO-01` and retain it through layout changes. Add **“Content reference: HOME-HERO-01”** as secondary text in the note so the photographer can identify an item when sending files or feedback.

A placeholder note has four small parts:

1. A plain-language heading: **“Add your opening photograph.”**
2. A specific request: **“Choose one strong recent wedding image you want new couples to remember.”**
3. A useful constraint or context: **“Send the original file. We will check desktop and phone crops together.”**
4. An honest next action/reference: **“Send with reference HOME-HERO-01”** and, where implemented, **“View in content checklist.”**

Use “Replace” for supplied material that needs a change and “Add” for an empty slot. Include an Upload action if the implementation accepts and saves files. A shared register and agreed folder handoff suffice for the first version.

**Replacement without unnecessary software**

Use one content checklist as the shared register. Its minimum fields are: **slot ID, page/section, item requested, supplied file/link/text, status, remaining note**. Add credit/usage confirmation where relevant and whether the final site requires the slot. Keep private client details or correspondence out of public files.

Use an agreed existing folder or document for the handoff. Suggested folder references include `content-handoff/HOME-HERO-01/`, `content-handoff/STORY-A-GALLERY-01/` and `content-handoff/ABOUT-PORTRAIT-01/`; the team has not created these folders. Preserve original filenames. Enter text beside its slot and supply a film through an authorised source link or file.

Generate local notes and the draft checklist from the same register. A static review page suffices. Consider a CMS or uploader after choosing the maintainer and update workflow.

Proposed visible statuses:

- **Needs content:** the owner has not supplied usable material; keep the request visible.
- **Received: checking:** the owner supplied material; the agent must check identity, rights, wording and display suitability before marking it Ready.
- **Needs an update:** explain the specific issue, for example **“This file is too small for the opening image. Please send the original camera export.”** Preserve the existing submission/reference.
- **Ready:** the agent checked the facts, usage/credit and intended display in the correct slot.
- **Not needed:** the team removed an optional item from scope and recorded the reason.

Define and update the denominator before showing counts such as “8 of 14 items ready.” Count one gallery as one group through curation. Link each incomplete entry to its location. The agent must check the material before marking it Ready; an owner clicking a button does not replace that check.

**Review supplied material**

Replace the placeholder with the supplied material, keep the content reference and review status beside it in the draft, and provide a concise issue note only if something remains unresolved. For a photograph, show the actual intended crop at desktop and phone sizes during review. For a story, verify names, sequence and context. For a review, preserve the supplied meaning and attribution. For contact, verify the destination before enabling delivery.

After checking an item, replace its prompt with a secondary **“Content added: ready”** note. Keep the overall draft notice until preparing the public release.

**Honest forms, films and links**

- An enquiry form with no configured recipient must say **“Draft enquiry form. Add the receiving address before this can send.”** It may demonstrate fields/validation, but must not transmit or display a fabricated received confirmation. A disabled submit control needs adjacent explanatory text; do not rely on a tooltip.
- After configuring delivery, distinguish sending, confirmed receipt/storage, failure and retry. Test delivery to an agreed destination within authorization. Do not count a WhatsApp tap or email-app launch as a received enquiry.
- Leave film placeholders static and state that the film is missing. Check supplied films for playback, title/credit and accessibility before marking them Ready.
- Label unknown social/contact destinations as missing and leave them inactive. Use a confirmed alternative contact path if the team omits the form.

**Preparing the public version**

Keep missing slots visible in the first owner review. Before an authorized public release, supply cleared content, redesign around available facts or omit optional sections. Resolve business identity, representative permitted work and a working contact path. Remove draft guidance and check for dummy destinations, sample reviews, invented promises or fake film/form behavior.

Remove notes and residual placeholder content from the public build, including metadata, structured data, image descriptions, accessible labels and search previews. Hiding notes with CSS leaves the underlying content unresolved. Check owner-review and public copy for **zero U+2014 em dashes**, including literal examples, status labels, accessible text and metadata. Protect sensitive or uncleared preview material with access controls; `noindex` does not restrict access.

Record missing content and continue independent design work with labelled placeholders. Apply these checks within the existing authorization; the user's placeholder instruction does not authorize website coding.

**Acceptance checks for the future first version**

1. Every missing item has a visible, specific note at its intended location, including on mobile; no hover-only instructions.
2. The local note and shared checklist resolve to the same stable slot ID, requested material and current status.
3. The photographer can identify what to supply and where to put/send it without using a custom CMS or asking what a generic “replace here” means.
4. The photographer can identify sample text/media as draft material. The draft contains no fake identity, proof, price, review, film playback or enquiry success.
5. Supplied material can move through received, needs-update and ready states without losing the original reference; adding a file does not imply rights or quality verification.
6. The owner can see unresolved optional sections in the review. The team can omit them before publication but must resolve required identity/work/contact gaps.
7. The agent checks content readiness or records its redesign/omission before removing draft guidance and residual placeholder metadata.
8. The agent finds zero U+2014 em dashes in owner-facing and public text, including accessible text and metadata.
